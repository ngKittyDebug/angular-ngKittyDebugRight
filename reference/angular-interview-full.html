Angular Interview — полный справочник

113 вопросов RS School с ответами уровня Excellent: trade-offs, сравнения подходов, привязка к ngKittyDebug (Angular 22, standalone, signals, Vitest, Taiga UI). Источник: angular.dev.

General

1. Что такое Angular и для чего он используется?

Angular — TypeScript-фреймворк для SPA и progressive web apps от Google. Даёт полный стек: компонентная архитектура, DI, маршрутизация, формы, HTTP, i18n, тестирование. Компилятор (AOT) превращает шаблоны в эффективный JS; рантайм управляет change detection и lifecycle.

Используют для enterprise SPA, админок, дашбордов — где важны структура, типобезопасность, долгосрочная поддержка и единые паттерны команды. Angular 16+ — standalone-first, signals, zoneless-ready.

vs React/Vue: больше «batteries included», круче learning curve, но меньше ad-hoc решений. Angular 22 в ngKittyDebug — не legacy NgModules, а современный standalone + signals стек.

2. Что такое Angular CLI и каковы его основные функции?

ng CLI — официальный toolchain: scaffold (ng generate), dev server (ng serve), production build (ng build), тесты (ng test), lint, deploy helpers. Оборачивает esbuild/Vite (Angular 17+) и управляет angular.json.

Ключевые функции: генерация standalone components/directives/pipes с правильными imports; path aliases; schematics для миграций; application builder с code splitting; SSR/hydration scaffolding.

Проект: pnpm start → ng serve -o; pnpm test → Vitest через Angular builder; префикс селекторов ngKitty из angular.json.

3. Что такое модуль в Angular, и какова его роль в приложении?

Исторически NgModule группировал declarations, imports, exports, providers — единица компиляции и lazy loading. Root AppModule bootstrap'ил приложение.

Современно (Angular 15+): standalone components заменяют модули. Bootstrap через bootstrapApplication(AppComponent, appConfig); providers в ApplicationConfig; lazy routes через loadComponent / loadChildren без feature modules.

NgModules ещё встречаются в legacy и библиотеках, но новый код — standalone. «Модуль» на интервью 2026 = логический feature boundary (features/main/), не обязательно @NgModule.
Проект: нет AppModule — только app.config.ts + feature folders с route-scoped providers.

4. Что такое межкомпонентное взаимодействие в Angular? Опишите различные способы передачи данных между компонентами (например, @Input/@Output, сервисы с Observables и т. д.).

Способы передачи данных и событий:

  • @Input / @Output (или input() / output()) — parent ↔ child, явный контракт.
  • Services + signals/Observable — shared state между несвязанными компонентами (AuthService, uiStateStore).
  • Route params / queryParams — данные через URL; withComponentInputBinding() биндит в signal inputs.
  • Facades — UI читает один orchestration API вместо прямых service calls.
  • Content projection — ng-content для composition.
Input/Output — для локальной иерархии. Services — для cross-cutting domain. Не злоупотребляй глобальным state для parent-child — усложняет тесты и traceability.
Проект: MainComponent → MainPageFacade (не HTTP напрямую). uiStateStore синхронизирует тему/язык с Firestore при auth.

Components

5. Что такое компоненты в Angular и как они являются основой структуры приложения?

Компонент = класс + шаблон + стили + metadata. Это минимальная единица UI: Angular создаёт instance, привязывает данные к шаблону, запускает change detection. Дерево компонентов = дерево приложения.

Standalone components (дефолт в CLI) явно объявляют imports: [...] — зависимости видны в файле, tree-shaking лучше чем у NgModule barrel exports.

Проект: feature layout: features/main/ui/main.component.ts + дочерние tarot-oracle, tarot-reading; shared CardComponent в shared/ui/.

6. Как настраивается селектор, шаблон и стиль компонента с помощью декоратора @Component?

@Component({
  selector: 'ngKitty-main',
  standalone: true,
  imports: [TarotOracleComponent, TranslocoPipe],
  templateUrl: './main.component.html',
  styleUrl: './main.component.scss',
  changeDetection: ChangeDetectionStrategy.OnPush, // опционально в A22
})

selector — CSS-селектор для использования в шаблонах. template / templateUrl — inline или внешний HTML. styles / styleUrl(s) — encapsulation через emulated (дефолт), ShadowDom или None.

Inline template удобен для tiny components; внешние файлы — для readability и Prettier. styleUrl (singular) — Angular 17+ вместо styleUrls.

7. Как вы объясните жизненный цикл компонента и его основные методы (например, ngOnInit, ngOnChanges, ngOnDestroy)?

Хуки (реализуют interfaces, вызываются фреймворком):

  • ngOnChanges — при изменении @Input (не для signal inputs).
  • ngOnInit — после первого init inputs; одноразовая setup-логика.
  • ngDoCheck — custom CD hook (редко).
  • ngAfterContentInit/Checked — projected content.
  • ngAfterViewInit/Checked — ViewChild доступен; осторожно с CD loops.
  • ngOnDestroy — cleanup subscriptions, timers.

В signals-era часть логики переезжает в constructor + effect() + afterNextRender(). ngOnInit всё ещё каноничен для side effects после DI.

Не ставь тяжёлую логику в ngAfterViewChecked — вызывается очень часто. Предпочитай effect() для реакции на signal changes.

8. Как работает двустороннее связывание данных в Angular, и в чем отличие от одностороннего связывания данных?

Одностороннее: [value]="expr" (property binding) или (event)="handler" (event binding). Данные текут в одну сторону — предсказуемо, OnPush-friendly.

Двустороннее: [(ngModel)]="field" — синтаксический сахар для [ngModel] + (ngModelChange). Требует FormsModule. В reactive forms — явно formControlName + valueChanges, без banana-in-box.

[(ngModel)] удобен в простых template-driven формах; в сложных — reactive forms дают типизацию, тестируемость, sync validators. Signal forms (experimental) — будущая альтернатива.
Проект: registration/login — typed reactive forms + FormBuilder.nonNullable; не ngModel на auth flows.

9. Отдельные компоненты.

Standalone components (standalone: true) — самодостаточны: сами импортируют directives, pipes, child components. Не нужен NgModule wrapper. Дефолт в Angular 19+ CLI.

Bootstrapping: bootstrapApplication(AppComponent, appConfig). Роуты lazy-load standalone через loadComponent: () => import(...).then(m => m.X). Libraries экспортируют standalone API.

Standalone упрощает mental model и tree-shaking. Миграция legacy: ng generate @angular/core:standalone. Все компоненты ngKittyDebug — standalone.

10. Что такое ViewChild и ViewChildren?

@ViewChild(Selector) — ссылка на один child в template компонента (компонент, directive, ElementRef). Доступен после ngAfterViewInit. Signal-версия: viewChild(), viewChildren() — реактивно, без static timing pitfalls.

@ContentChild / contentChild() — projected content через ng-content.

Императивный доступ к DOM/child — escape hatch. Предпочитай data binding и signal inputs. ViewChild оправдан для focus(), scroll, интеграции с non-Angular widgets (Taiga overlays).

11. В чем разница между ElementRef и Renderer2?

ElementRef — обёртка над native DOM element. .nativeElement даёт прямой доступ — опасен (XSS при user content, ломает SSR abstraction).

Renderer2 — platform-agnostic API для DOM mutations: setStyle, addClass, listen. Работает в SSR/web worker contexts. В modern Angular предпочитай host bindings в декораторе или hostDirectives.

ElementRef — только для trusted low-level cases. Для стилей/классов — [class.x], [style.x] или host metadata. Renderer2 реже нужен с signals + host bindings.

12. Как работают декораторы HostBinding и HostListener?

@HostBinding('class.active') — привязка свойства host element. @HostListener('click') — подписка на DOM events host'а.

Современная замена: host: { '[class.active]': 'isActive()', '(click)': 'onClick()' } в @Component / @Directive — всё в metadata, без отдельных декораторов.

Проект: ScanEffectDirective — signal inputs + declarative host bindings для CSS custom properties и классов.

13. Каков механизм обнаружения изменений в Angular, и в чем разница между стратегиями Default и OnPush? Когда лучше использовать каждую из них?

Change Detection (CD) обходит дерево компонентов, сравнивает bindings. Default — проверяется при любом async event (Zone.js) или явном markForCheck. OnPush — только при: input reference change, event в компоненте, async pipe emit, signal read, explicit markForCheck.

Angular 22: OnPush — дефолт. Signals интегрированы в CD graph — чтение signal в шаблоне автоматически помечает view dirty.

OnPush + immutable data + signals = предсказуемая perf. Default проще для новичков, но риск лишних проверок. Zoneless apps полагаются на signals/events без Zone patching.

14. Как вы обрабатываете динамические компоненты?

Три паттерна:

  1. ViewContainerRef.createComponent() — императивно, полный lifecycle control.
  2. NgComponentOutlet — декларативно в шаблоне.
  3. Dialog/overlay services — Taiga TuiDialogService, CDK Overlay.
Dynamic components обходят compile-time checks. Предпочитай static imports + @if / lazy loadComponent где возможно.
Проект: ModalService — Taiga dialogs. Profile — ngTemplateOutlet для переключения шаблонов вместо dynamic component.

Directives

15. Что такое директивы в Angular и для чего они используются?

Директива — класс с @Directive, меняющий поведение/вид DOM без собственного шаблона (в отличие от компонента). Атрибутные — классы, стили, listeners (ngClass, ScanEffectDirective). Структурные — добавляют/убирают DOM (*ngIf, @if).

Компонент технически — директива с template. Переиспользуемая логика DOM лучше в directive, чем copy-paste в компонентах.

16. В чем разница между структурными и атрибутными директивами?

Атрибутные меняют существующий element: [ngClass], [ngStyle], custom [ngKittyScanEffect]. Element остаётся в DOM.

Структурные (префикс *) — microsyntax для ng-template: создают/уничтожают embedded view. *ngFor = template + ViewContainerRef.

Angular 17+ control flow (@if, @for) — встроенные structural blocks, быстрее и читабельнее legacy *ngIf. Атрибутные директивы по-прежнему актуальны.
Проект: шаблоны на @if/@for; атрибутная ScanEffectDirective на tui-root.

17. Как создать и использовать собственную директиву? Объясните @Directive.

@Directive({
  selector: '[ngKittyScanEffect]',
  standalone: true,
  host: {
    '[class.scan-active]': 'scanEnabled()',
    '(mouseenter)': 'onEnter()',
  },
})
export class ScanEffectDirective {
  scanEnabled = input(true);
}

Standalone directive добавляется в imports компонента. input() / output() — signal API. inject() для сервисов.

Директива vs компонент: нет template — только поведение на host. Директива vs service: нужен доступ к ElementRef/DOM/render context.

18. Объясните ngIf и ngFor и их использование.

*ngIf="condition" — создаёт view только при truthy condition; else / then templates для ветвления. *ngFor="let item of items; trackBy: trackFn" — итерирует коллекцию, создаёт view per item.

Современная замена:

@if (reading()) { <tarot-reading /> }
@for (card of cards(); track card.id) { <ngKitty-card /> }

track обязателен в @for — identity для DOM reuse, как trackBy.

Проект: main.component.html, altar.component.html — @if/@for, не legacy structural directives.

19. В чем разница между *ngIf и [hidden]?

*ngIf — не создаёт DOM при false; уничтожает component tree, освобождает память, не гоняет CD для скрытого контента.

[hidden]="true" — element в DOM, CSS display: none. Component жив, подписки активны, CD может проверять.

hidden — быстрое toggle без destroy/init cost (tabs с частым переключением). ngIf/@if — тяжёлые виджеты, условный рендер, экономия памяти. @if предпочтительнее *ngIf в новом коде.

20. Какова цель ngSwitch, ngSwitchCase и ngSwitchDefault?

Multi-way branching без вложенных *ngIf: [ngSwitch]="value" + *ngSwitchCase + *ngSwitchDefault. Показывает один matching case.

@switch (role()) {
  @case ('oracle') { <oracle-view /> }
  @case ('seeker') { <seeker-view /> }
  @default { <fallback /> }
}
@switch читабельнее цепочки @if/@else if при 3+ ветках. Для 2 веток — достаточно @if/@else.

21. В чем разница между ngStyle и ngClass?

[ngClass] — объекты/массивы/строки CSS-классов: [ngClass]="{ active: isActive(), disabled: loading() }".

[ngStyle] — inline styles object: [ngStyle]="{ 'font-size.px': size() }".

Предпочтительно: [class.active]="isActive()", [style.width.px]="w()" — проще, меньше directive overhead.

ngClass/ngStyle полезны при динамических наборах из computed object. Статические биндинги — native syntax.

22. Что такое ngContainer и для чего он используется?

ng-container — логический wrapper без DOM element. Группирует structural directives без лишнего div:

<ng-container *ngIf="show">
  <h2>Title</h2>
  <p>Body</p>
</ng-container>

С @if часто не нужен — block syntax не требует wrapper. Остаётся для ngTemplateOutlet, multi-directive grouping.

Проект: profile использует ngTemplateOutlet с ng-container для conditional templates.

23. Как создать собственные структурные директивы с использованием ng-template?

Инжектируй TemplateRef + ViewContainerRef. Создавай/очищай embedded views:

@Directive({ selector: '[appUnless]' })
export class UnlessDirective {
  private readonly tpl = inject(TemplateRef);
  private readonly vcr = inject(ViewContainerRef);
  @Input() set appUnless(cond: boolean) {
    this.vcr.clear();
    if (!cond) this.vcr.createEmbeddedView(this.tpl);
  }
}
Custom structural directives — редко нужны с @if/@for. Оправданы для domain-specific DSL (permissions, feature flags as structural).

Pipes

24. Что такое пайпы, и для чего они предназначены в Angular?

Pipe — чистая (обычно) transform-функция в шаблоне: {{ value | pipeName:arg }}. Декоратор @Pipe({ name, standalone: true }). Разделяет presentation logic от component class.

Используют для форматирования дат, валют, truncate, i18n display. Pure pipes кэшируются per binding per CD cycle.

25. Можете ли вы привести примеры некоторых встроенных пайпов (например, date, uppercase, lowercase)?

  • date — {{ ts | date:'shortDate' }}
  • uppercase / lowercase / titlecase
  • currency, decimal, percent
  • json — debug
  • slice, keyvalue, async
Проект: TranslocoPipe для i18n вместо built-in i18n pipe; date в profile/shrift при необходимости.

26. В чем разница между 'чистыми' и 'не чистыми' пайпами?

Pure (default) — пересчитывается только при изменении input reference или args. Кэш на уровне binding.

Impure (pure: false) — вызывается каждый CD cycle. Опасно для perf на hot paths.

Impure оправдан для async-like transforms без async pipe (редко). Предпочитай pure + immutable inputs или computed() в компоненте вместо impure pipe.

27. Как использовать несколько пайпов одновременно?

Цепочка слева направо: {{ name | lowercase | slice:0:10 | uppercase }} — каждый pipe получает output предыдущего.

Порядок важен: {{ date | date:'medium' | uppercase }} vs {{ date | uppercase }} (бессмысленно для Date).

28. Как передать параметры в пайп?

Colon-separated args после name: {{ text | slice:0:limit() }}. Pipe class:

transform(value: string, start = 0, end?: number): string {
  return value.slice(start, end);
}

Args должны быть immutable-friendly — примитивы или stable references для pure pipe cache.

29. Каковы преимущества асинхронных пайпов? Как применить с Observable или Promise?

async pipe подписывается на Observable/Promise, unwrap value в шаблон, авто-unsubscribe при destroy. Триггерит OnPush при новых emits.

@if (user$ | async; as user) { {{ user.name }} }

Современная альтернатива: toSignal(obs$) в классе — явнее, лучше с signals templates: {{ user()?.name }}.

async pipe — меньше boilerplate в шаблоне. toSignal — единый signals model, проще тестировать class logic. В ngKittyDebug преобладают signals, не async pipe.

30. Как происходит процесс регистрации собственного пайпа в модуле?

Standalone: @Pipe({ standalone: true }) + добавить в imports компонента — NgModule не нужен.

Исторически: declarations + exports в NgModule. Root import через shared barrel.

Pipe для display-only transform. Сложная бизнес-логика — в facade/computed, не в pipe (тестируемость).

31. Как обрабатывать сложные преобразования в пайпах?

Держи pipe pure и deterministic. Тяжёлые вычисления — memoization в injectable service или computed(). Для коллекций — track в @for, не transform в pipe каждый CD.

Несколько параметров, optional args, locale-aware formatting через inject(LOCALE_ID). Unit-test: new MyPipe().transform(input, arg) без TestBed.

Если pipe нуждается в DI сервисах и state — возможно, это должен быть computed signal или метод facade, не pipe.

Routing

32. Что такое маршрутизация в Angular, и для чего она используется?

Client-side router сопоставляет URL → компонент (view). SPA без full page reload. Поддерживает nested routes, guards, resolvers, lazy loading, params, history API.

provideRouter(routes, withComponentInputBinding(), withPreloading(...)) в app.config.ts.

Проект: app.routes.ts — layout shell + lazy feature routes (main, altar, shrift, sanctum, profile, auth).

33. Как настроить базовую систему маршрутизации с RouterModule и router-outlet?

Legacy: RouterModule.forRoot(routes) в AppModule.

Modern: provideRouter(routes); в shell template <router-outlet />. Nested: child routes рендерятся в outlet родительского routed component.

export const routes: Routes = [
  { path: '', component: LayoutComponent, children: [...] },
  { path: '**', loadComponent: () => import('./not-found')... },
];

34. Как использовать параметры маршрута и queryParams?

Route params: /user/:id → ActivatedRoute.paramMap или signal input id = input.required<string>() с withComponentInputBinding().

Query: ?lang=ru → queryParamMap / queryParams. Navigate: router.navigate(['/path'], { queryParams: { lang: 'ru' } }).

Params — identity ресурса в path. Query — optional filters/state. Signal inputs из route — меньше boilerplate чем subscribe в ngOnInit.

35. Можете ли вы привести пример использования дочерних маршрутов?

{
  path: '',
  component: LayoutComponent,
  children: [
    { path: '', loadComponent: () => import('./main')... },
    { path: 'altar', loadComponent: () => import('./altar')... },
  ],
}

LayoutComponent содержит <router-outlet> + chrome (header, sidebar). Children swap в outlet. Relative navigation: routerLink="altar" от current activated route.

Проект: LayoutComponent — persistent sidebar/header; features — child routes.

36. Какие существуют стратегии предварительной загрузки?

  • NoPreloading — только on-demand (default).
  • PreloadAllModules — все lazy chunks после bootstrap (legacy name; работает с loadComponent).
  • Custom PreloadingStrategy — preload(route, load) return Observable; selective preload.
Проект: UserStateStrategy — прелоадит guest routes для неавторизованных, auth routes для залогиненных.

37. Как использовать Route Guards (CanActivate и CanDeactivate)?

Functional guards (modern): CanMatchFn, CanActivateFn, CanDeactivateFn — чистые функции с inject().

export const authGuard: CanMatchFn = () =>
  inject(AuthService).isAuthenticated() || inject(Router).createUrlTree(['/login']);

export const dirtyFormGuard: CanDeactivateFn = () =>
  !inject(FormFacade).isDirty() || confirm('Leave?');
canMatch — блокирует route matching (лучше для lazy + auth split). canActivate — после match. Проект использует canMatch для auth/guest разделения.
Проект: authGuard, guestGuard, dirtyFormGuard на registration.

38. Что такое ActivatedRoute, и как его использовать?

Сервис с snapshot текущего route segment: params, queryParams, data, fragment. Observable streams (paramMap) эмитят при navigation.

С withComponentInputBinding() — предпочитай signal input() от route params. ActivatedRoute нужен для imperative subscribe или parent/child param traversal (route.parent).

39. Как обрабатывать ленивую загрузку в маршрутизации?

loadComponent: () => import('./feature').then(m => m.FeatureComponent) — отдельный JS chunk. loadChildren — для child route arrays или legacy modules.

Route-level providers создают injector на время visit. Guards (canMatch) решают до загрузки chunk.

Lazy = smaller initial bundle, но latency при первом visit. PreloadingStrategy балансирует. Все feature routes ngKittyDebug lazy-loaded кроме shell.

RxJS

40. Определите концепцию RxJS и ее использование в Angular.

RxJS — Reactive Extensions для JS: Observable как push-based коллекция во времени. Angular использует для HttpClient, Router events, form valueChanges, interceptors.

В Angular 22 RxJS чаще на async-границах; UI state — signals. @angular/core/rxjs-interop: toSignal, toObservable, rxResource, takeUntilDestroyed.

Не переписывай всё в signals — RxJS силён в композиции async. Не держи UI state в Subjects — signals проще.

41. Что такое Observable, Observer и Subscriptions?

  • Observable — ленивый producer; логика в subscribe.
  • Observer — { next, error, complete }.
  • Subscription — handle от subscribe; unsubscribe() отменяет work и HTTP.

HttpClient subscribe → network request; unsubscribe → abort (XHR/fetch).

43. Можете ли вы привести примеры основных операторов RxJS в Angular?

  • map, filter, tap, catchError
  • switchMap — отмена предыдущего (search)
  • mergeMap — параллель (N HTTP chunks)

44. Как создать собственный Observable с new Observable()?

45. Что такое Subject и BehaviorSubject?

  • Subject — multicast, hot, нет initial value.
  • BehaviorSubject — хранит current value; новые subs получают последнее.
  • ReplaySubject(n) — replay last N.

Исторически app state. Сейчас — signal() / signalStore. Subjects — event bus, legacy interop.

BehaviorSubject ≈ signal с худшим template DX. Root Subject без complete — leak risk.
Проект: нет BehaviorSubject — uiStateStore, facades на signals.

46. Как вы объясните концепции Горячих и Холодных Observables?

Cold — producer per subscriber (HttpClient, ajax). Hot — shared producer (DOM events, Subject, shareReplay).

shareReplay({ bufferSize: 1, refCount: true }) — cold→hot с auto-teardown.

Dependency Injection

50. Что такое Dependency Injection, и каковы ее цели в Angular?

DI — паттерн: класс получает зависимости извне через constructor/inject(), не создаёт их сам. Angular Injector разрешает token → instance по иерархии.

Цели: testability (mock providers), loose coupling, lifecycle control (singleton vs per-route), composable app config.

51. Как создать сервис и использовать его в компонентах?

@Injectable({ providedIn: 'root' })
export class AuthService {
  private readonly auth = inject(Auth);
}

@Component({ ... })
export class LoginComponent {
  private readonly auth = inject(AuthService);
}

Или constructor injection. Сервис — обычный класс с @Injectable; Angular создаёт instance при первом inject.

Проект: кастомный @Service() декоратор оборачивает @Injectable({ providedIn: 'root' }) для единообразия.

52. В чем разница между providedIn: 'root', providedIn: 'any' и регистрацией провайдера в разделе "providers" NgModule?

  • providedIn: 'root' — app singleton, tree-shakeable если не используется.
  • providedIn: 'any' — новый instance per lazy-loaded bundle (редко).
  • providers: [S] в component/route/module — instance per injector scope.
Root для true singletons (AuthService). Route providers для feature isolation (MainPageFacade).

53. Что такое useClass, useValue и useFactory?

  • useClass: MockAuth — подмена реализации (тесты).
  • useValue: { apiUrl: '/api' } — константа/объект.
  • useFactory: () => new S(inject(X)) — динамическое создание.
  • useExisting — alias на другой token.
{ provide: API_URL, useValue: environment.apiUrl }
{ provide: TarotService, useClass: MockTarotService }

54. Объясните концепцию Injector и иерархии провайдеров.

Environment injectors: platform → root (app.config) → route injectors. Element injectors: per component/directive, child ищет вверх.

Resolution: element injector chain → environment injector branch → root. Child provider shadows parent token.

55. Что такое DI-токен, и как его использовать?

InjectionToken<T> — typed key для non-class dependencies:

export const API_URL = new InjectionToken<string>('api.url');
inject(API_URL); // в компоненте/функции

Также interface tokens, multi tokens (HTTP_INTERCEPTORS), ENVIRONMENT_INITIALIZER.

Проект: UI_STATE token для uiStateStore injection.

56. Как использовать декораторы @Optional, @Self и @SkipSelf для управления внедрением зависимостей и их обработкой?

Параметры inject():

  • optional: true — null если нет provider.
  • self: true — только текущий element injector.
  • skipSelf: true — пропустить текущий, искать у parent.
  • host: true — до host component.

Используй для optional parent refs, library components, избежания circular DI.

57. Как внедрять зависимости на основе условий?

useFactory с inject(ENV) для environment-specific impl. EnvironmentProviders в условных import. Route-level providers для per-feature impl.

Anti-pattern: if/else в constructor — лучше strategy pattern или отдельные tokens per environment file.

58. Что такое мульти-провайдер и как его настроить?

providers: [
  { provide: HTTP_INTERCEPTORS, useClass: LogInterceptor, multi: true },
  { provide: HTTP_INTERCEPTORS, useClass: AuthInterceptor, multi: true },
]
// Modern: withInterceptors([logFn, authFn])

Injector собирает массив всех registrations для token. Порядок важен для interceptor chain.

59. Как реализовать внедрение зависимостей для отдельных компонентов?

@Component({ providers: [LocalService] }) — новый instance per component instance. viewProviders — только для view children, не projected content.

Route providers — scope на visit route subtree. Destroyed при navigation away.

Проект: MainPageFacade, TarotService на main route; SanctumRitualService на sanctum.

60. Как можно повторно использовать отдельные компоненты в различных частях приложения?

Standalone component в shared/ui/ — импортируй в imports: [CardComponent] где нужно. Path aliases @shared/*. Не дублируй providers — stateless presentational components.

Smart/dumb split: shared dumb components + feature smart containers с facades.

Проект: CardComponent, DigitalPriestComponent в shared; features импортируют явно.

Forms

61. В чем разница между Template-driven Forms и Reactive Forms?

Template-drivenReactive

Быстрые простые формыСложная валидация, unit tests

62. Что такое FormControl, FormGroup и FormArray?

  • FormControl<T> — одно поле, value + validators + status.
  • FormGroup — объект полей, nested groups.
  • FormArray — динамический список controls (repeatable rows).
const form = fb.nonNullable.group({
  email: ['', [Validators.required, Validators.email]],
  passwords: fb.group({ pass: [''], confirm: [''] }),

63. В чем различия в работе с валидацией для Template-driven и Reactive Forms?

Reactive: validators в model (Validators.required, custom ValidatorFn); sync/async на control level; form.errors, control.hasError('email').

Template-driven: HTML attributes (required, minlength) + directive validators; состояние через ngModel refs (#email="ngModel").

Reactive — validators тестируются без DOM. Template — быстрее прототип, хуже scale.

64. Как реализовать собственные валидаторы для форм?

export const passwordConfirmationValidator = (...): ValidatorFn =>
  (control) => {
    const group = control.parent;
    // cross-field: set errors on sibling, return null on group
    return null;
  };

Sync: ValidatorFn. Async: AsyncValidatorFn returns Observable/Promise. Group-level для cross-field.

Проект: passwordConfirmationValidator — сохраняет unrelated errors на sibling control; unit-tested без TestBed.

65. Как можно извлечь и обработать данные из форм после их отправки?

Reactive: if (form.invalid) return; const value = form.getRawValue(); — typed object. form.disable() during submit. Facade orchestrates API call + error state.

Template-driven: ngSubmit + ngForm.value если valid. Предпочитай facade method submit() — UI не знает про HTTP.

Проект: LoginFacade.login(), RegisterPageFacade — validate → auth API → navigate/toast.

66. Что такое двустороннее связывание данных в контексте Template-driven Forms?

[(ngModel)]="name" синхронизирует input ↔ component property через NgModel directive. Требует name attribute для registration в parent ngForm.

Удобно для прототипов. В production forms ngKittyDebug — reactive: explicit control, no ngModel banana-in-box.

67. Как использовать FormBuilder?

private readonly fb = inject(FormBuilder);
readonly form = this.fb.nonNullable.group({
  sin: ['', Validators.required],
});

nonNullable — controls не принимают null (Angular 14+ typed forms). Shorthand vs new FormGroup({...}).

68. Как отслеживать состояние изменения форм или элементов управления формой (например, touched, dirty)?

  • dirty — value changed from initial.
  • touched — blur event.
  • pristine / untouched — opposites.
  • valid / invalid, pending (async validators).

UI: показывай errors только touched && invalid. dirtyFormGuard использует form.dirty для canDeactivate.

Проект: dirtyFormGuard на registration route.

69. Как обрабатывать асинхронную валидацию?

// AsyncValidatorFn returns Observable<ValidationErrors|null>
return http.get(`/api/check?email=${v}`).pipe(

Control pending while async runs. Debounce via timer(300) + switchMap in validator. Не блокируй UI без индикатора.

Lazy Loading

70. Что такое Lazy Loading, и для чего она используется?

Отложенная загрузка feature code в отдельных JS chunks до первого visit на route. Уменьшает initial bundle, ускоряет TTI. Angular router + dynamic import().

Trade-off: latency при первом navigation vs smaller bootstrap. Preloading смягчает.

71. Как настроить ленивую загрузку для конкретного модуля?

Legacy NgModule: loadChildren: () => import('./feature/feature.module').then(m => m.FeatureModule).

Modern standalone: loadComponent: () => import('./feature.component').then(c => c.FeatureComponent) или loadChildren: () => import('./routes').then(m => m.FEATURE_ROUTES).

Проект: все features через loadComponent — profile, login, altar, shrift, sanctum, ball.

72. Какие изменения в системе маршрутизации необходимы?

  • Route entry с loadComponent / loadChildren вместо синхронного component:.
  • Feature providers на route level (providers: [Facade, ApiService]).
  • Guards (canMatch) до chunk load.
  • Build config — application builder автоматически code-splits.

73. Каковы преимущества использования ленивой загрузки?

  • Меньший initial bundle → faster first paint.
  • Изоляция feature providers/injectors.
  • Parallel chunk loading в браузере.
  • Natural feature boundaries для команд.

74. Что такое стратегия предварительной загрузки, и какие основные стратегии используются для предварительной загрузки модулей (NoPreloading или PreloadAllModules)?

NoPreloading — chunks только on-demand. Минимальный network после bootstrap, но wait при первом click.

PreloadAllModules — idle-time preload всех lazy routes. Быстрее subsequent navigation, больше background traffic.

Для auth-aware apps custom strategy лучше обоих — не грузи sanctum guest'у.

75. Как использовать PreloadingStrategy с Angular Router?

provideRouter(routes, withPreloading(UserStateStrategy))

@Injectable({ providedIn: 'root' })
export class UserStateStrategy implements PreloadingStrategy {
  preload(route: Route, load: () => Observable<unknown>) {
    return this.shouldPreload(route) ? load() : of(null);
  }
}
Проект: UserStateStrategy — conditional preload по auth state.

76. Какие недостатки ленивой загрузки?

  • First-visit latency (network round-trip).
  • Сложнее shared singletons — нужен root vs route scope discipline.
  • Duplicate dependencies в chunks без careful sharing.
  • Debugging split bundles сложнее monolith.

77. Как отлаживать проблемы ленивой загрузки?

  • Network tab — chunk 404/500, wrong path in import().
  • ng build --stats-json + webpack-bundle-analyzer / source-map-explorer.
  • Router config tracing: withDebugTracing() в dev.
  • Проверь export name в .then(m => m.Component) — typos = runtime error.

Modules

78. Что такое Модуль в Angular, и какова его роль в приложении?

@NgModule — metadata container: declarations (components/pipes/directives), imports, exports, providers, bootstrap. Роль: compilation boundary, encapsulation exports, lazy loading unit.

В Angular 22 роль переняли standalone + route config. «Модуль» = feature folder, не обязательно NgModule.

Standalone эквивалент: каждый component declares own imports: []; shared providers в route или providedIn.

80. Как можно разделить функциональность на различные модули и подключить их к основному модулю приложения?

Legacy: FeatureModule imported в AppModule или lazy loadChildren.

Modern: features/<name>/ с data/, facades/, ui/; route entry в app.routes.ts с loadComponent.

Проект: canonical pattern в features/main — API service → Facade → UI; route-scoped providers.

HTTP

81. Что такое HttpClientModule, и почему он важен?

Исторически NgModule для регистрации HttpClient. Современно: provideHttpClient(withInterceptors([...]), withXhr()) в app.config.ts.

Даёт typed HTTP, interceptors, progress events, JSON parsing, XSRF support.

Проект: provideHttpClient(withXhr(), withInterceptors([httpErrorInterceptor])).

82. Как можно делать HTTP-запросы с помощью HttpClient?

private readonly http = inject(HttpClient);
getReading(p: TarotParams) {
  return this.http.get<TarotResponse>(url, { params: { ...p } });
}

Cold Observable — lazy until subscribe. Options: headers, params, responseType, observe, reportProgress, context.

Проект: TarotService, MyMemoryTranslationService, TranslocoHttpLoader.

83. Можете ли вы объяснить разницу между Observables и Promises в HTTP?

HttpClient returns Observable: cancellable via unsubscribe, composable (retry, switchMap), multi-event with observe: 'events'. Promise — eager, single value.

firstValueFrom(http.get(...)) — bridge для async/await в guards/resources.

84. Как обрабатывать ошибки во время HTTP-запросов?

Defense in depth: interceptor (global toast) → facade (domain error signal) → component (display). catchError + HttpErrorResponse typing.

Проект: interceptor skips /i18n/; MainPageFacade maps errors to signal.

85. Какие техники оптимизации HTTP и кэширования?

  • shareReplay dedup; Resource API dedup by params.
  • In-memory Map cache (PriestQuotesService).
  • Batching: forkJoin, concurrency mergeMap(n).
  • Lazy routes + selective preloading.

86. Какова цель HttpInterceptor и как он работает?

Chain между app и network: (req, next) => next(req.clone(...)).pipe(...). Functional HttpInterceptorFn + withInterceptors. Immutable req.clone.

87. В каких сценариях interceptor для обработки ошибок?

Глобальный toast, logging, 401 redirect. Не для feature-specific validation messages — используй HttpContext tokens для opt-out.

88. Как обрабатывать аутентификацию через HTTP-интерсепторы?

Attach Bearer token: req.clone({ setHeaders: { Authorization: `Bearer ${token}` }}). AuthZ на сервере; client-side route guards для UI protection.

ngKittyDebug: Firebase Auth через SDK, не Bearer — guards вместо auth interceptor. REST+JWT apps — interceptor standard.
Проект: authGuard/guestGuard как CanMatchFn.

Signals

98. Что такое Signals?

Reactive primitive: signal(initial) holds value; readers track dependency graph. computed() derives; effect() side effects. Fine-grained updates без full tree CD scan.

Основа state model в Angular 16+; интегрированы в templates, inputs, router, forms (experimental).

99. Как читать и изменять значение signal?

const count = signal(0);
count();        // read
count.set(5);   // replace
count.update(v => v + 1);  // mutate based on current

Read в computed/template/effect регистрирует dependency. Write через set/update/mutate (objects).

100. Какова основная выгода signals вместо примитивов?

Примитив в class — change detection не знает об изменении без markForCheck/zone. Signal — framework отслеживает reads, точечно обновляет views. computed кэширует derived values.

Не заменяет RxJS для event streams — дополняет для sync/reactive UI state.
Проект: facades expose readonly loading = this._loading.asReadonly().

101. В чем преимущество сигнальных входов?

role = input<TarotRole>('oracle');
intent = input.required<string>();

Type-safe, callable in class (this.role()), integrates with transforms, required variant. Заменяет @Input() + ngOnChanges.

Signal inputs — default в new components. Legacy @Input для interop libraries.

102. Как подписаться на signal?

Signals не имеют subscribe API — это не Observable. «Подписка» = effect(() => { console.log(count()); }) или computed или template read {{ count() }}.

Для bridge к RxJS: toObservable(signal). Из Observable: toSignal(obs$).

103. Можно ли читать signal из computed без создания зависимости?

Да — untracked(() => otherSignal()) внутри computed или effect. Читает current value без регистрации dependency.

Use case: logging, compare with previous, read config that shouldn't trigger recompute.

104. Обнаружение изменений signal с использованием API effect()

effect(() => {
  const lang = this.activeLang();
  document.documentElement.lang = lang;
});

effect runs after CD, tracks signal reads, re-runs on change. onCleanup for teardown. Не мутируй signals в effect (risk loops) — prefer derived computed.

Проект: uiStateStore — effects sync theme to DOM + Firestore.

105. Какова связь между signals и обнаружением изменений?

Template/control flow reads signals → view records dependencies → signal change marks dirty views only. OnPush default works naturally. Path to zoneless: signals + async events trigger updates without Zone.js.

linkedSignal — writable derived that resets when source changes (MainPageFacade reading state).

106. Как обрабатывать отладку сигналов?

  • Angular DevTools — signal graph inspection.
  • effect(() => console.log('[debug]', state())) — temporary.
  • isDevMode() guards on debug effects.
  • NgRx Signals DevTools plugin for stores.
  • Unit tests: read facade.loading() directly — no DOM needed.

Angular 16, 17, 18+

107. Что нового в версиях Angular 16, 17 и 18?

  • 16: signals (developer preview), required inputs, destroyRef, esbuild optimizer.
  • 17: control flow (@if/@for), deferrable views, standalone default, new app builder.
  • 18: signals stable, zoneless preview, Material 3, server routing, resource() preview.
  • 19–22: signal inputs/outputs default, incremental hydration, linkedSignal, rxResource stable, Vitest default.
Проект: Angular 22 — полный modern stack из списка выше.

108. Опишите новые возможности @if, @for, @switch, @defer.

@defer — in-template perf. loadComponent — route-level. ngKittyDebug: control flow yes, @defer no (uses route lazy + preloading).

109. Можете ли вы объяснить преимущества использования нового рендерера Angular Ivy, представленного в Angular 18?

Ivy (с Angular 9+) — AOT compilation, tree-shakable components, smaller bundles, improved DI, local template compilation. К Angular 18 Ivy зрелый: faster build (esbuild), better HMR, partial compilation for libraries.

На интервью: Ivy = compile-time template → instructions; не interpret templates at runtime. Enables standalone, tree-shaking, defer blocks.

Вопрос часто путают «новый рендерер в 18» — уточни: Ivy давно default; в 18+ улучшения builder/hydration/zoneless, не смена Ivy.

110. Как Angular 18 улучшает производительность и оптимизацию размера пакета по сравнению с предыдущими версиями?

  • esbuild/Vite application builder — faster builds, better code splitting.
  • Control flow — less runtime directive code.
  • Zoneless — remove zone.js (~30KB) when ready.
  • Defer + lazy routes — smaller initial chunks.
  • Signals — granular CD, fewer full tree walks.

111. Какие улучшения или дополнения были внесены в Angular Material в последних версиях?

Material 3 design tokens, theming API refresh, improved accessibility, density controls. В ecosystem ngKittyDebug используется Taiga UI, не Material — но принципы те же: design tokens, CDK overlays, form field patterns.

Taiga — меньше community vs Material, но лучше кастомный visual identity проекта (delulu-church aesthetic).
Проект: provideTaiga(), TuiDialogService, tui-root shell, custom CSS variables в styles.css.

112. Как Angular 18 поддерживает серверный рендеринг (SSR) и какие улучшения он предлагает в этой области?

ng add @angular/ssr — server-side rendering + hydration. Incremental hydration (19+) — hydrate visible parts first. Event replay — не терять clicks до hydration. provideClientHydration().

ngKittyDebug — client-only SPA on Netlify, no SSR. Знать концепцию для интервью: SEO, TTFB, hydration mismatch pitfalls.

113. Обсудите любые обновления или улучшения, внесенные в Angular CLI и его функции в последних релизах.

  • Application builder (esbuild) replaces browser builder.
  • Standalone schematic default; ng generate signal inputs.
  • Vitest as test runner option (default in 21+).
  • ng update migrations for control flow, standalone, inject().
  • SSR/hydration schematics; environment builder configs.
Проект: pnpm + Angular CLI 22; pnpm typecheck, pnpm lint, pnpm test в pre-flight checklist.
