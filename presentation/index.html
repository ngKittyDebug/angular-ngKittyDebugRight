Architecture
Decision 1

Facade pattern

Выбрали · UI → Facade → Service

Альтернатива: компонент сразу инжектит сервис.

Почему: UI не знает про Firebase/HTTP; проще тесты и review.
Минус: больше файлов, выше порог входа — учились вместе.

Architecture
Decision 2

Firebase Auth + Firestore

Выбрали · один вендор для auth и данных

Альтернатива: Netlify Identity + отдельное хранилище / свой бэкенд.

Почему: uid сразу связан с sins, candles, uiState.
Минус: сложнее SDK; ошибки ≠ HttpClient.

Architecture

Part 2 · Failure

Real story

Миграция mid-project

Что сломалось

Стартовали с Netlify Identity. Auth и данные пользователей разъехались — sins/candles нужны на uid.

Что пробовали

Alena — разведка Firebase. Daria — переписала AuthService + UserProfileService. По сути миграция посреди спринта.

Чем закончилось

Один Firebase-слой, история Login→Confess→Altar→Profile заработала. Побочный эффект: два потока ошибок (HttpClient interceptor ≠ Firestore SDK) — компромисс до сих пор.
